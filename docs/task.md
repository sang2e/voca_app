# Task Guide - Word Learning MVP

이 문서는 Claude Code가 영어 단어 학습 MVP 화면을 구현하기 위한 작업 지시서입니다.

Claude Code는 작업 전 `common.md`, `policy.md`, `task.md`를 먼저 읽고, 해당 규칙을 기준으로 구현합니다.

---

# 0. 역할

당신은 React 기반 프로젝트에서 모바일 UI를 구현하는 시니어 퍼블리셔입니다.

이번 작업의 목적은 기능 개발이 아니라, 레퍼런스 이미지를 기준으로 화면 UI를 정확하게 구현하는 것입니다.

백엔드 연동, Supabase 연동, 인증 처리, 실제 데이터 저장 로직은 이번 작업 범위에서 제외합니다.

이번 단계에서는 아래 작업에만 집중합니다.

- 디자인 구현
- 모바일 UI 구성
- 컴포넌트 구조화
- 반응형 퍼블리싱
- 사용자 경험 흐름 구현

---

# 1. 이번 작업 범위

## 포함

- 화면 레이아웃 구현

- 카드형 UI 구현

## 제외

- Supabase 연동

# 2. 프로젝트 개요

## 2.1 프로젝트명

영어 단어 학습 MVP

---

## 2.2 목적

사용자가 직접 단어장을 만들고, 영어 단어를 저장한 뒤, 플래시카드 학습과 객관식 퀴즈를 통해 단어를 외울 수 있는 모바일 중심 학습 앱을 구현합니다.

이 앱은 공무원 시험 준비 전용 앱이 아닙니다.

레퍼런스 이미지 중 공무원 단어앱 화면은 UI/UX 흐름과 다크 테마 감성을 참고하기 위한 용도이며, 서비스 컨셉은 일반 영어 단어 학습 앱으로 유지합니다.

---

## 2.3 핵심 방향

- 퀴즈 중심 영어 단어 암기 앱
- 직접 단어장 생성 가능
- 직접 단어 입력 가능
- 플래시카드 기반 학습 가능
- 객관식 퀴즈 가능
- 오답 복습 가능
- 라이브러리에서 단어장 관리 가능
- 모바일 앱 같은 몰입형 UX

---

## 2.4 핵심 UX 방향

이번 프로젝트에서 가장 중요한 것은:

- 퀴즈를 계속 풀고 싶게 만드는 UX

입니다.

단순 CRUD 앱처럼 만들지 않습니다.

아래 UX를 가장 중요하게 생각합니다.

- 빠른 화면 전환
- 몰입감 있는 학습 흐름
- 큰 터치 영역
- 최소 입력
- 카드 기반 학습
- 다크 테마 기반 집중감
- 모바일 앱 같은 사용감
- 직관적인 퀴즈 경험

---

## 2.5 테마 정책

기본 테마는 dark mode 입니다.

하지만 구조는 반드시:

- dark / light mode 둘 다 지원 가능하게

작성합니다.

### 필수 조건

- 색상 하드코딩 금지
- theme token 기반 구조
- 추후 light mode 확장 가능해야 함
- bg-black / text-white 반복 금지
- Tailwind dark mode 확장 고려
- 공통 색상 구조 유지

Claude Code는 이미지 레퍼런스를 보고 아래를 참고합니다.

## 8.2 컴포넌트 레퍼런스 사용 규칙

`docs/references/components` 내부 코드는 복붙용이 아니라 구현 스타일 참고용입니다.

아래 항목을 우선 참고합니다.

- 컴포넌트 구조 방식
- 함수 분리 스타일
- Tailwind 작성 방식
- 이벤트 핸들러 분리 방식
- 접근성 처리 방식
- props 네이밍 방식
- 주석 작성 방식

주의:

- 기존 코드를 그대로 복사하지 않습니다.
- 현재 프로젝트 구조에 맞게 재구성합니다.
- API나 비즈니스 로직이 강하게 섞인 기존 컴포넌트는 참고하지 않습니다.

---

## 8.3 Store 레퍼런스 사용 규칙

`docs/references/store` 내부 코드는 Zustand store 구조 참고용입니다.

아래 store를 참고합니다.

```txt
useZuModal.jsx
useZuToast.jsx
useZuViewport.jsx
```

아래 항목만 참고합니다.

- store 작성 방식
- state/action 네이밍 방식
- modal open/close 구조
- toast 호출 구조
- viewport 상태 관리 방식
- setter 함수 구조
- 전역 UI 상태 관리 패턴

주의:

- 기존 store를 그대로 복사하지 않습니다.
- MVP 1차 작업에서는 단어 목록, 퀴즈 데이터, 학습 데이터는 Zustand에 저장하지 않습니다.
- 이번 단계에서 Zustand는 아래처럼 전역 UI 상태가 필요할 때만 사용 가능합니다.

```txt
- modal
- toast
- viewport
- theme
```

아래 데이터는 Zustand 사용 금지입니다.

```txt
- 단어 목록
- 단어장 데이터
- 퀴즈 데이터
- 학습 데이터
- API 응답 데이터
```

# 10. 퀴즈 UX 방향

퀴즈 화면은 이번 프로젝트의 핵심입니다.

단순 문제 출력처럼 만들지 않습니다.

중요 UX:

- 빠른 문제 전환
- 몰입감 있는 화면
- 큰 선택 버튼
- 직관적인 정답/오답 표현
- 현재 진행률 표시
- 최소한의 입력
- 한 손 조작 고려

---

# 11. 플래시카드 UX 방향

플래시카드 화면은:

- 단순 단어 리스트가 아니라 집중형 학습 화면

이어야 합니다.

중요 요소:

- 큰 단어 카드
- swipe 또는 next 기반 이동 구조 고려
- 이전/다음 흐름 명확
- 현재 진행률 표시
- 학습 상태 표현 가능 구조

# 15. 토큰 절약 작업 방식

Claude Code는 작업 중 불필요한 설명과 반복 확인을 최소화합니다.

---

## 15.1 문서 참조 방식

작업 시작 시 아래 문서를 한 번만 읽고 핵심 규칙을 기억한 뒤 작업합니다.

```txt
docs/common.md
docs/policy.md
docs/task.md
```

작업 중 같은 문서를 반복해서 다시 읽지 않습니다.

단, 규칙 충돌이 있거나 구현 기준이 불명확한 경우에만 필요한 섹션만 다시 확인합니다.

---

## 15.2 응답 방식

- 변경 파일 목록만 요약합니다.
- 핵심 변경사항만 짧게 설명합니다.
- 전체 파일 코드를 매번 출력하지 않습니다.
- 사용자가 요청한 경우에만 전체 코드를 보여줍니다.
- 긴 설명보다 실제 코드 변경을 우선합니다.
- 작업 완료 후 “무엇을 수정했는지”만 간단히 정리합니다.

---

## 15.3 질문 최소화

명확하지 않은 부분은 먼저 기존 문서와 레퍼런스 이미지를 기준으로 판단합니다.

단, 아래처럼 결과물이 크게 달라질 수 있는 경우에만 질문합니다.

- 라우트 구조가 충돌하는 경우
- 레퍼런스 이미지 해석이 애매한 경우
- 컴포넌트 책임이 불명확한 경우
- 화면 UX 방향이 서로 충돌하는 경우

단순 스타일, 여백, 카드 구조, 버튼 형태 등은 레퍼런스를 기준으로 판단하고 바로 구현합니다.

---

## 15.4 최소 수정 원칙

- 요청받은 범위의 파일만 수정합니다.
- 기존 구조를 불필요하게 갈아엎지 않습니다.
- 기존 컴포넌트가 있으면 먼저 재사용을 검토합니다.
- 새 컴포넌트는 2회 이상 반복되거나 명확히 분리 가치가 있을 때만 만듭니다.
- 불필요한 폴더 생성, 파일 이동, 네이밍 변경을 하지 않습니다.
- 기능 범위를 벗어난 리팩토링을 하지 않습니다.

---

# 16. 주석 작성 규칙

Claude Code는 퍼블리싱 코드 작성 시 필요한 위치에 주석을 작성합니다.

---

## 16.1 주석 필수 위치

아래 영역에는 주석을 작성합니다.

- 화면의 큰 섹션 구분
- 주요 UI 블록
- 반복되는 카드/리스트 영역
- 이벤트 핸들러
- 상태 계산 함수
- className 계산 함수
- 레퍼런스 이미지 기준으로 구현한 특이 UI

---

## 16.2 주석 예시

```jsx
{/* 상단 헤더 영역 */}

  ...
</header>

{/* 오늘 학습 요약 카드 */}
<section>
  ...
</section>
```

```jsx
// 퀴즈 보기 버튼 스타일
```

---

## 16.3 주석 작성 기준

- 주석은 짧고 명확하게 작성합니다.
- 코드와 같은 말을 반복하는 주석은 작성하지 않습니다.
- 복잡한 로직은 왜 필요한지 설명합니다.
- JSX 섹션 주석은 퍼블리셔가 구조를 빠르게 파악할 수 있게 작성합니다.
